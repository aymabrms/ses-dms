# Repeating Sections

The source questionnaires use fixed paper rows and numbered blanks. The system should treat repeatable information as variable-length data because household size, employee count, tenants, structures, and project feedback are not naturally fixed.

## Fixed-column risk

Fixed fields such as `member1`, `member2`, `employee1`, or `tenant1` would make reporting and validation fragile. They would require schema changes or awkward blank columns when counts vary. They also make cross-record validation harder, such as computing household size, age distribution, sex disaggregation, and employee totals. A repeatable record model is required for accurate summaries and exports.
